# ADR 0003. Разрешения: классы инструментов и голосовое подтверждение через хук

**Статус:** принято
**Дата:** 2026-08-26

## Контекст

Голосовая команда открывает доступ к агенту, который умеет исполнять команды
оболочки и править файлы. Микрофон при этом горячий круглосуточно. Это делает
политику разрешений не удобством, а частью защиты.

Что даёт платформа (проверено на Claude Code 2.1.245 и Codex 0.147.0, 2026-08-26):

- `claude --settings <file-or-json>` — подключение дополнительного файла настроек на
  один запуск, без изменения глобального конфига пользователя;
- `claude --permission-mode` со значениями `acceptEdits`, `auto`, `bypassPermissions`,
  `manual`, `dontAsk`, `plan`;
- `claude --allowedTools` / `--disallowedTools`, `--add-dir`;
- в финальной строке потока присутствует массив `permission_denials`;
- `codex exec --sandbox` со значениями `read-only`, `workspace-write`,
  `danger-full-access`; интерактивных запросов в `exec` нет.

## Решение

**Три класса инструментов**, задаются на проект в реестре:

- `allow` — исполняется без вопросов: чтение, поиск, правки внутри разрешённых
  каталогов;
- `confirm` — требует произнесённого «да»: команды оболочки, запись за пределами
  правок, сетевые обращения;
- `deny` — не исполняется никогда.

**Механизм подтверждения.** Aura генерирует временный файл настроек с хуком
`PreToolUse` и передаёт его через `--settings`. Хук — крошечный исполняемый файл
`aura-hook`, который подключается к локальному сокету и блокируется до вердикта.
Пока он ждёт, Aura формулирует вопрос через SLM, произносит его и слушает короткую
грамматику подтверждения без кодового слова.

**Отказ по умолчанию.** Таймаут 20 секунд, нераспознанный ответ и любая ошибка канала
дают `deny`. Для голосового интерфейса к shell-агенту допустим только такой порядок:
неуверенность означает отказ.

**`bypassPermissions` не используется никогда** — ни в конфиге, ни как аварийный путь.

**Codex в v1 работает в песочнице `workspace-write` без голосового подтверждения.**
В неинтерактивном режиме `exec` эскалации не запрашиваются; действия за пределами
песочницы просто не происходят. Это сужение зафиксировано осознанно.

## Последствия

**Хорошее.** Опасное действие не исполняется без произнесённого согласия. Глобальная
конфигурация пользователя не изменяется. Отказы видны в потоке событий и попадают в
журнал. Codex остаётся ограничен песочницей, а не доверием.

**Плохое.** Появляется четвёртый исполняемый артефакт (`aura-hook`) и синхронный путь
через локальный сокет — источник блокировок и таймаутов, который нужно тестировать
отдельно. Латентность подтверждения складывается из генерации вопроса, синтеза,
произнесения и распознавания ответа: несколько секунд, в течение которых агент стоит.

**Асимметрия агентов.** Claude Code получает подтверждения, Codex — нет. Пользователю
это должно быть видно, иначе поведение выглядит непредсказуемым.

## Рассмотренные альтернативы

**Только allowlist, всё остальное — автоматический отказ.** Проще и безопаснее, но
агент упирается на реальных задачах, и польза от голосового интерфейса падает.

**`bypassPermissions` в доверенных каталогах.** Отвергнуто: превращает голосовую
команду в неограниченный доступ к оболочке. Несовместимо с горячим микрофоном, даже
при верификации диктора.

**Инструмент запроса разрешений через MCP.** В текущей версии CLI соответствующий
флаг в справке отсутствует; путь через хук проверяем и не зависит от неподтверждённой
поверхности.

# ADR 0001. Политика исполнения: устройство на стадию

**Статус:** принято
**Дата:** 2026-08-26

## Контекст

Исходное требование звучало как «модели работают только на NPU; если NPU нет —
внешняя GPU; если и её нет — приложение сообщает об ошибке». Требование было
уточнено до «iGPU задействовать можно, но энергоэффективность очень важна».

Измерения целевой машины (OpenVINO 2026.3.0, 2026-08-26):

```
NPU: Intel AI Boost · DEVICE_ARCHITECTURE 3720 · NPU_MAX_TILES 2
     OPTIMIZATION_CAPABILITIES: FP16, INT8, EXPORT_IMPORT
     NPU_DEVICE_ALLOC_MEM_SIZE: 0
GPU: Intel Arc 140T (16GB) · FP16, INT8, GPU_HW_MATMUL, GPU_USM_MEMORY
CPU: Core Ultra 9 285H — 6P + 8E + 2LP-E
```

Три факта определяют решение:

1. **Дискретной GPU в машине нет и не будет.** Формулировка «откат на внешнюю GPU»
   на этом железе не срабатывает никогда, то есть буквальное прочтение исходного
   требования означает «NPU или ничего».
2. **NPU архитектуры 3720 не заявляет INT4.** Для авторегрессивного декода языковой
   модели INT4 и есть источник скорости; без него декод на NPU проигрывает iGPU,
   у которого вдобавок есть `GPU_HW_MATMUL`.
3. **Постоянно работающий детектор на NPU вредит именно тому, ради чего NPU брали.**
   Тридцать с лишним инференсов в секунду круглосуточно не дают устройству уснуть.
   Накладные расходы на постановку задачи превышают сам расчёт для модели весом в
   пару мегабайт.

## Решение

Устройство назначается **на стадию**, по форме вычисления, а не по типу устройства:

| Класс вычисления | Устройство | Стадии |
|---|---|---|
| постоянный детектор без нейросети | CPU, LP-E ядра | энергетический и спектральный гейт |
| статические формы, кодировщики | **NPU** | VAD, кодовое слово, диктор, распознавание речи |
| авторегрессивный декод, динамические формы | **iGPU** | нарративная SLM, синтез речи |

Дополнительно:

- **Молчаливого отката на CPU для тяжёлых моделей нет.** Отсутствие NPU — это
  внятная ошибка с указанием драйвера, а не тихая деградация, которую пользователь
  замечает по севшей батарее.
- **Устройство каждой стадии — строка в конфиге**, не константа в коде. Перенос
  стадии между NPU и GPU не требует пересборки и не является изменением архитектуры.
- Инференсы на NPU сериализуются очередью с приоритетами: кодовое слово > диктор >
  VAD > распознавание. `NPU_MAX_TILES: 2` не даёт рассчитывать на широкий параллелизм.

## Последствия

**Хорошее.** Каждая стадия исполняется там, где её форма вычисления родная. В тишине
не работает ни одна нейросеть. Пользователь может переназначить устройство, не
трогая код, и померить разницу.

**Плохое.** Обязательство поддерживать два ускорителя и путь на CPU для гейта — три
разных профиля производительности вместо одного. Диагностика усложняется: «медленно»
теперь требует уточнения, на какой стадии и на каком устройстве.

**Принятый риск.** Работоспособность привязана к наличию NPU. На машине без NPU
приложение не запустится по замыслу, а не по недосмотру.

## Рассмотренные альтернативы

**Буквально только NPU, включая гейт и SLM.** Отвергнуто: постоянный детектор на NPU
увеличивает расход батареи, а декод SLM без INT4 упирается в производительность и
блокирует NPU, из-за чего распознавание не может идти во время озвучки.

**Всё на iGPU.** Отвергнуто: NPU в этом случае простаивает, а iGPU конкурирует с
графикой рабочего стола; постоянный детектор на GPU по энергетике заведомо хуже
LP-E ядра.

**Лестница с откатом на CPU.** Отвергнуто как поведение по умолчанию: тихий откат
маскирует отсутствующий драйвер и превращает энергетический регресс в невидимый.
Ручное переключение через конфиг остаётся доступным.

## Доказательства

`Core().available_devices` и `get_property` по каждому устройству, снятые на целевой
машине 2026-08-26; вывод целиком приведён в разделе 5.1 архитектурного дизайна.

# ADR 0004. Топология агентской сессии: долгоживущий процесс на проект

**Статус:** принято
**Дата:** 2026-08-26

## Контекст

Голосовой интерфейс живёт короткими репликами. Пользователь ставит задачу, слышит
ход работы, уточняет на ходу, останавливает. Если каждая реплика поднимает новый
процесс агента, к каждой добавляется холодный старт: загрузка конфигурации, хуков,
навыков, разогрев контекста — единицы секунд. На фоне бюджета «конец фразы → задача
принята ≤ 1.2 с» это неприемлемо.

Что даёт платформа (проверено 2026-08-26):

- `claude -p --input-format stream-json --output-format stream-json` — потоковый ввод
  **и** вывод в одном долгоживущем процессе: новая реплика уходит строкой в stdin, без
  перезапуска;
- `claude --session-id <uuid>`, `--resume`, `--fork-session`;
- `codex exec` читает инструкции один раз, потоковый ввод отсутствует; продолжение —
  через `codex exec resume --last` или по идентификатору.

## Решение

**На каждый активный проект — один долгоживущий процесс агента.** Реплики уточнения
уходят в stdin того же процесса. Супервизор в `aura-tray` отвечает за жизненный цикл:
запуск, перезапуск после падения, остановку по таймауту простоя, убийство дерева
процессов по стоп-слову.

Параметры запуска для Claude Code:

```
claude -p --input-format stream-json --output-format stream-json
       --include-partial-messages --session-id <uuid>
       --add-dir <project> --settings <сгенерированный файл>
```

**Асимметрия для Codex.** Потокового ввода у `codex exec` нет, поэтому каждая реплика
запускает `codex exec resume` поверх предыдущей нити. Контекст сохраняется, холодный
старт остаётся. Асимметрия описана явно, а не скрыта общим интерфейсом: `AgentSession`
имеет две реализации с разными характеристиками латентности.

**Таймаут простоя.** Процесс без активности установленное время завершается, состояние
сессии остаётся в `--session-id` и восстанавливается через `--resume`. Ресурсы в
простое не удерживаются.

## Последствия

**Хорошее.** Уточнение на ходу становится дешёвым, и это то, ради чего голосовой
интерфейс имеет смысл. Контекст живёт в агенте, Aura не дублирует историю диалога.
Стоп-слово получает конкретный объект для убийства.

**Плохое.** Процесс висит в памяти между репликами. Нужен супервизор с политикой
перезапуска и таймаутом — узел, которого не было бы при разовых запусках. Падение
агента в середине задачи требует осмысленного восстановления, а не простого повтора.

**Асимметрия.** Латентность уточнения у Claude Code и Codex различается заметно.
Пользователю это видно; в документации это должно быть названо, а не замаскировано.

## Рассмотренные альтернативы

**Разовый запуск на задачу с `--resume`.** Проще, в простое не тратит ничего, но
добавляет холодный старт к каждой реплике и не даёт вмешаться в идущую работу.

**MCP или app-server.** Строго типизированный протокол вместо разбора вывода CLI.
Отвергнуто для v1: часть поверхности помечена экспериментальной и различается у двух
CLI, риск поломки на обновлении выше выигрыша.
